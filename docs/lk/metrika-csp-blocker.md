# Метрика в кабинете не работает: её блокирует CSP

Проверено 13.09.2026 на `https://lk.navilet.ru/start`.

## Что происходит

Код счётчика в HTML кабинета есть, но браузер его не исполняет. Текущий заголовок:

```
content-security-policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline';
img-src 'self' data: blob: https:; font-src 'self' https://fonts.gstatic.com;
connect-src 'self'; frame-ancestors 'self';
```

- `script-src 'self'` — не даёт загрузить `https://mc.yandex.ru/metrika/tag.js` и не даёт выполнить инлайн-код счётчика;
- `connect-src 'self'` — не даёт отправить данные на `mc.yandex.ru`, даже если скрипт бы загрузился.

## Чем это обходится

Счётчик 108200337 — общий для `navilet.ru` и `lk.navilet.ru` (кабинет добавлен зеркалом). За всё время с 23 марта Метрика записала на `lk.navilet.ru` **4 просмотра страниц**. За это же время только с июля кнопку регистрации на сайте нажали **58 уникальных человек** — все они уходили в кабинет.

То есть вся воронка после перехода на сайт невидима: мы не знаем ни сколько человек доходит до формы регистрации, ни сколько её заканчивает, ни какой канал приводит платящих.

Отдельно: это блокирует «Правку 4. События Метрики» из документа `registraciya-korrektirovki.md`. Даже если добавить вызовы `reachGoal`, они не долетят — скрипт счётчика не загружен.

## Что нужно сделать

**1. Разрешить домены Метрики в CSP.** К существующим директивам добавить:

```
script-src  'self' https://mc.yandex.ru https://yastatic.net;
connect-src 'self' https://mc.yandex.ru wss://mc.yandex.ru;
child-src   blob: https://mc.yandex.ru;
frame-src   blob: https://mc.yandex.ru;
```

`wss:` и `child-src`/`frame-src` нужны для вебвизора. `img-src` менять не нужно — там уже разрешён `https:`.

**2. Решить вопрос с инлайн-кодом.** Разрешённый домен сам по себе не поможет: код счётчика вставлен инлайн, а `'unsafe-inline'` в `script-src` мы добавлять не предлагаем. Два варианта:

- **Проще:** вынести инициализацию счётчика в собственный файл (например `/js/metrika.js`) и подключить обычным `<script src="/js/metrika.js">`. Он пройдёт по `'self'`, а сам `tag.js` подтянется с разрешённого `mc.yandex.ru`.
- **Строже:** оставить инлайн, но выдавать на каждый запрос случайный `nonce` и указывать его и в заголовке (`script-src 'nonce-...'`), и в атрибуте `nonce` тега `<script>`.

Официальная инструкция Яндекса: <https://yandex.ru/support/metrica/ru/code/install-counter-csp>

**3. Не терять параметры в URL.** С 13.09 сайт передаёт в кабинет метку источника: `https://lk.navilet.ru/start?from=demo_hero&version=pro`. Значения `from`, `plan`, `version` нужны в аналитике, поэтому важно, чтобы они не отрезались при редиректах и сохранялись, если человека уводит на авторизацию и возвращает обратно.

## Как проверить, что починилось

1. Открыть `https://lk.navilet.ru/start` в браузере, вкладка Console — не должно быть ошибок вида `Refused to load the script 'https://mc.yandex.ru/metrika/tag.js'`.
2. Вкладка Network — запрос к `mc.yandex.ru/watch/108200337` со статусом 200.
3. В Метрике: Отчёты → Содержание → Популярное — в списке должны появиться адреса `lk.navilet.ru`; Отчёты → Содержание → Параметры URL — должен появиться параметр `from`.
4. Через сутки: Отчёты → Посетители → Посещаемость с фильтром по `lk.navilet.ru` показывает ненулевые цифры.

После этого имеет смысл возвращаться к целям из «Правки 4» — тогда они будут работать.
